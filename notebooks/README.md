# REPAIR-X — Offline Experimental Analysis Notebook

## Contents

- `REPAIR-X_Experimental_Analysis.ipynb`: **executed**, documented, source-verified metrics and graphs for the 300-trial principal batch.
- `data/evaluation_300_curated.csv`: **300 trial-level records** derived from batch `2298cd6ffd37484789857f402f0a889c`, with no generated patches, API keys, prompt text, stack traces, or secrets.
- `figures/*.png`: export-ready graphs (regenerated by running all cells).
- `figures/evaluation_provider_statistics.csv`: reproducible aggregated table.
- `requirements-notebook.txt`: extra analysis dependencies, separate from the existing application `requirements.txt`.

## Use (Windows / Conda)

From `D:\MINOR_PROJECT\REPAIR-X-starter`:

```bat
conda activate repairx
python -m pip install -r notebooks/requirements-notebook.txt
jupyter notebook notebooks/REPAIR-X_Experimental_Analysis.ipynb
```

In Jupyter, select **Kernel -> Restart Kernel and Run All Cells**. Or open the `.ipynb` in VS Code and click **Run All**.

The notebook is **offline** and requires no API keys or outbound API calls. It does not import the REPAIR-X repair engine or execute code generated by LLMs.

## Provenance and interpretation

Source: `REPAIR-X-starter(20261122-084745).zip`, files `evaluation_summary_2298cd6f.csv` and `evaluation_trials.jsonl`, filtered to the **exact** principal batch `2298cd6ffd37484789857f402f0a889c`. Curated columns include outcomes, latency, repair/formatting retries, per-trial risk summaries, and final validation outcomes. Test assertion counts are not conflated with trial counts. The raw JSONL data are intentionally **not** committed.

Repeated 10 fault scenarios × 3 providers × 10 repetitions = 300 trials; not 300 unique bugs. Observed acceptance is not evidence of general correctness or security. The public website is a static reviewer; the notebook analyzes the local test-validated benchmark.
